## 启动流程（`src/main.ts` → `bootstrap()`）

```
bootstrap()
  1. setupStore(app)              — Pinia + pinia-plugin-persistedstate
  2. registerDirectives(app)      — v-permission / v-role
  3. app.use(router)              — 先挂路由（Sentry 等需 router 实例）
  4. setupPlugins(app, router)
     └─ setupErrorHandler         — Vue / window 全局错误
     └─ setupElementPlus          — 图标等
     └─ setupI18n                 — vue-i18n
     └─ setupSentry               — 可选，无 DSN 则跳过
  5. await router.isReady()       — 首屏前执行完相关守卫/解析
  6. app.mount('#app')
  7. initWebVitals()              — CLS / INP / LCP / FCP / TTFB
```

## 路由流程（`src/router/guards.ts` 摘要）

```
beforeEach: NProgress.start
  无 token
    白名单路径（/login, /register, /forgot-password）或 meta.requiresAuth === false → 放行
    否则 → /login?redirect=…
  有 token 且目标为 /login → /
  有 token 但 userInfo 未加载 → fetchUserInfo，失败则 logout 并回登录
  动态路由未加载（!permissionStore.isRoutesLoaded）
    → generateRoutes() → 对每个动态路由 router.addRoute('Layout', route) → return { ...to, replace: true }
  合并 matched 的 meta.permissions，若非空且用户无任一对应权限（userStore.hasPermission）→ /403
  否则 → 放行
（RouteMeta 中的 meta.roles 已声明，当前 beforeEach 未做角色路由校验；按钮/区块可用 v-role 或 usePermission().hasRole()。）
afterEach:
  设置 document.title
  tabsStore.addTab(to)
  NProgress.done
onError: NProgress.done + 控制台错误
```

## HTTP 层特性（`src/utils/http`）

- **401**：若存在 `refreshToken` 则单飞刷新，队列中请求刷新完成后带新 `Authorization` 重放；无 `refreshToken` 或刷新失败时走登录过期确认框（`skipAuthRefresh` 可关闭整套逻辑以避开递归）。
- **去重与取消**：`cancelDuplicate: true` 时同 `requestKey`（默认 `METHOD:url`）取消进行中的旧请求，基于 `AbortController` 与内部 `pendingRequests` Map；导出 `cancelRequest` / `cancelAllRequests`。
- **重试**：`retryCount` > 0 且 HTTP 状态 ≥ 500 时指数退避后重发（**401/403 不参与**）。
- **成功判断**：`ResponseData` 的 `code` 须等于 `getApiSuccessCode()`（`config`）。
- **提示与 Loading**：`showError` 默认 `true`；`showLoading: true` 时配对 `showLoading`/`hideLoading`（`loading.ts` 内计数）。
- **GET**：自动追加 `_t` 时间戳防缓存（除非业务另行处理）。

## 权限体系

| 层级           | 机制                                                                                                                                |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| 页面级         | 路由 `beforeEach` 中校验 `meta.permissions`（`userStore.hasPermission`；`permissions` 含 `*:*:*` 为超管时 `hasPermission` 恒 true） |
| 路由 meta 角色 | `RouteMeta.roles` 已定义，**当前路由守卫不校验**；需页面或组件内自判                                                                |
| 按钮级         | `v-permission` / `v-role` 与 `usePermission()`（`hasPermission` / `hasRole` 等）                                                    |

## 暗黑模式

- `appStore.setTheme('light' \| 'dark' \| 'system')`；`system` 使用 `matchMedia('(prefers-color-scheme: dark)')` 与 `change` 监听，并维护 `html` 的 `dark` 类；切换模式时会移除旧的 `system` 监听器（见 `app.ts`）。
- 样式侧配合 `assets/styles/variables.scss`、`dark.scss` 与 `element-plus/theme-chalk/dark/css-vars.css`（`main.ts` 引入顺序在注释中已说明）。

## CI/CD 与相关 Workflow

- **CI（`ci.yml`）**：`push`/`pull_request` 至 `main`、`master`、`develop` → 安装 → `pnpm audit --audit-level=high` → `lint` → `lint:style` → `type-check` → `test:run` → `build`。
- **生产部署（`deploy.yml`）**：`main` / `master` 上 `needs: check` 复用 `ci.yml`，再执行 Docker 构建/推送与远程部署（详见该文件）。
- **预发（`deploy-staging.yml`）**：`develop` 或手动 `workflow_dispatch`。
- **Lighthouse（`lighthouse.yml`）**：`pull_request` 至 `main` / `master` 等。
